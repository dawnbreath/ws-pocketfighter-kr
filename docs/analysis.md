# 포켓 파이터(WS) 한글화·컬러화 — 분석·분류·작업준비 결과

원본: `orig/pf.ws` (2MB, 흑백 WS, MD5 e79dddc7db77ad96c52b0b7690f8c1b1, SHA-256 b47c8692…905e). 원본 파일은 읽기 전용으로 보존.

## 1. ROM 구조
- 뱅크 매핑: 고정 영역(0x40000~0xFFFFF) = ROM 0x140000~0x1FFFFF(ROMBBSLCT=0xF). 게임은 가상 세그먼트를 씀.
  - `9000:972D` = 뱅크 0xE0+(seg>>12)를 포트 0xC3에 매핑(E 계열), `9000:974C` = 0xF0+(seg>>12)(F 계열)
  - `9000:96DB`(bx=포트<<8|뱅크) 매핑 + 직전값 보관, `9000:9776` 복원
- 빈 공간: 2MB가 거의 꽉 참(뱅크당 꼬리 수십~수백 바이트). → **4MB로 확장**
  - 원본 2MB를 0x200000 이후에 둠. 뱅크값 & 0x3F 매핑이라 기존 E0/F0 계열 번호가 그대로 원본을 가리킴
  - 새 뱅크 0x00~0x1F(포트값 0xC0~0xDF)를 한글 글꼴·대사·컬러 루틴에 사용
- 헤더: ROM 크기 0x04→0x06, 컬러 플래그 0→1, 체크섬 재계산

- 인코딩: Shift-JIS. 변환표 0x1CF070(124자)+0x1CF168(89자), 글꼴 8×16 2bpp(ROM 0xEBBDC / 0xECB9C).
- 대사 제어 코드: ＃N 줄바꿈, ＃P 페이지, ＃E 끝, ＃S/＃L 인자 없음, ＃F/＃T/＃W/＃M 인자 1, ＃C 인자 2. N/P/E 외 제어 코드는 모두 페이지 사이에만 있음.

- 이름 입력 화면: 없음(검색·플레이 확인).
- 영문 텍스트(BATTLE SELECT, OPTION 등)와 타이틀 로고: 지시대로 보류.

## 3. 한글 출력 방식
- 한글은 빌드할 때 **줄 단위로 갈무리11(12px, OFL)로 미리 렌더링**하고, 8×16 칸으로 잘라 칸마다 코드를 붙임(가변폭).
  - 코드: 첫 바이트 0xA0~0xFE(페이지), 둘째 바이트 1~254. 최대 24,130칸, 글꼴 뱅크 0x00부터 8페이지/뱅크
  - 원본 가나 1칸(8px)에 대해 한글 음절은 1.5칸(12px). 한 줄에 약 14~15음절
- 엔진 변경(텍스트 경로에만 적용):
  1. `5000:AFBA` → `krchk`: 첫 바이트 ≥0xA0이면 표 검색 없이 즉시 반환(한글은 원본보다 빠름)
  2. `5000:AEDF`, `9000:AC2A`의 페이지 선택 블록 → `fontsel`
  3. `5000:AF05`, `9000:AC4F`의 `lcall 4000:8F40` → `glyphcopy`(한글일 때만 뱅크 지정 후 원래 복사 루틴 재사용)
  4. `9000:C80F`, `9000:CA0A`(스토리 렌더러의 뱅크 지정) → 새 대사 뱅크
  - 스텁 136바이트를 뱅크 0x15 꼬리 빈 공간(5000:FF34~FFBB)에 배치
- 검증: v001(엔진만 탑재, 텍스트 원문) ↔ 원본, 동일 입력 화면 비교 5지점 픽셀 완전 일치. 시험 문장으로 스토리(스프라이트 경로)와 WONDER GATE(BG 경로) 한글 출력 확인.

## 4. 이미지 텍스트(일본어) 목록
- 스프라이트 스크립트(명령 04=타일 기준주소, 05=조각 목록)로 조립되는 라벨 104개
  - 아이콘 6(攻·回·避 등 1글자), 通信対戦·シングル·通信対戦ができません·通信·できません
  - 마이티콤보/필살기 Lv1~3 박스, キャラカード, 使う/使わない, 通常技/必殺技/回復/回避/ジェム/ＧＣ
  - 기술명 약 77개(한자·가타카나, 흰 글자·검은 바탕, 높이 16px)
- 타이틀 메뉴 「カードバトル」「カードギャラリー」(스프라이트, ROM 0xD0490 시트, 「カード」 줄 공유)
- 방식: 라벨별 조각 수·배치는 원본 그대로(=VRAM 타일 수 동일). 조각 목록의 타일 번호만 바꿔 한글 타일을 가리킴.
  - 사용 가능: 일본어 라벨 전용 타일 817개 + 뱅크 0x11 빈 공간 421개. 다른 그림과 공유되는 10타일은 보존
  - 한글 음절을 타일 격자에 맞춰 같은 음절은 타일 공유
- 배경 그림 속 간판 글자(스테이지 배경)는 장식 그림이라 대상에서 제외.

## 5. VRAM 0x4000~0xFDFF(아래쪽 2/3)
- 스토리·카드배틀·격투·옵션 경로에서 쓰기 감시 결과 게임 쓰기 0건(0x75AC의 8바이트는 Mednafen 내부 문자열).
- 이 게임은 글자를 ROM에서 칸마다 복사해 상주 글꼴이 필요 없음. 또한 스프라이트는 타일 뱅크1(0x4000~)을 쓸 수 없음.
  → 한글 글꼴을 VRAM에 올릴 필요는 없음. 이 영역은 비워 두고, 컬러화용 작은 상태값(0xFD80~0xFDFF)만 사용할 예정.
  → 이후 회귀 검증 때도 쓰기 감시 유지.

## 6. 컬러화 사전 확인
- 흑백 팔레트: 셰이드 LUT(포트 0x1C~0x1F)로 페이드, 팔레트(0x20~0x3F)는 여러 곳에서 직접 변경.
- VBlank 핸들러 `4000:03C0`, 진입부 `4000:03C4`(mov ax,0x1000; mov ds,ax)에 far call 하나로 훅 가능.
- 시험: 컬러 모드(포트 0x60=0x80) + 흑백 레지스터→회색조 변환으로 원본과 같은 화면 확인. 투명색 문제 없음.
  - 컬러 팔레트는 2bpp에서도 팔레트당 32바이트 간격(0xFE00+p*32).
